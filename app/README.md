# 곁마을 운영 대시보드: 개발·설정 안내

담당자가 바뀌어도 설정을 이어받을 수 있도록 남기는 문서입니다. 기능은 [PRD.md](../PRD.md), 설계 배경은 [TECH_DESIGN.md](../TECH_DESIGN.md), 단계별 진행은 [DEV_PLAN_STAGE0.md](../DEV_PLAN_STAGE0.md)·[DEV_PLAN_STAGE1.md](../DEV_PLAN_STAGE1.md)를 보세요.

## 1. 구성 한눈에 보기

```
브라우저 ──▶ Apps Script 웹앱 ──▶ 운영 DB (구글 시트)
                  │            └▶ 주민번호 파일 (구글 시트, 별도. 2단계부터 사용)
                  └▶ 구글폼 응답 시트 ×3 (읽기 전용, 3단계부터 사용)
```

| 파일 | 역할 |
|---|---|
| `appsscript.json` | 시간대(서울), 웹앱 설정(접속한 사용자 권한으로 실행), 권한 범위 |
| `Schema.gs` | **탭과 열 정의, 쓰기 허용 규칙의 단일 기준.** 열을 추가·수정할 때는 여기를 먼저 고친다 |
| `Lib.gs` | 순수 계산 함수 (이메일 정규화, 주민번호 모양 검사, 쓰기 검증, 이관 변환 규칙, 운영진 검증). 구글 서비스를 쓰지 않아 Node로 테스트됨 |
| `Db.gs` | 시트 읽기·쓰기 도우미, 잠금, 충돌 검사, 감사 기록, 백업 |
| `Setup.gs` | `setup()`: 폴더, 시트 2개, 탭, 초기 데이터 생성. 여러 번 실행해도 안전 |
| `Api.gs` | 화면이 부르는 서버 함수: 조회, 단계 체크, 정보 수정, 일괄 처리, 회차 관리 |
| `Legacy.gs` | 기존 엑셀 이관(미리보기, 실행, 되돌리기). 소유자 전용, 1회용 |
| `Staff.gs` | 운영진 추가·삭제와 드라이브 파일 공유. 소유자 전용 |
| `Code.gs` | 웹앱 진입점 `doGet()`. 접속자 이메일 확인 → 운영진 확인 → 화면 |
| `SelfTest.gs` | `runSelfTest()`: 서버 기능을 임시 복사본에서 시험 (4장) |
| `Index.html` | 화면의 틀. 로그인·권한 없음 안내 화면도 여기 있음 |
| `Style.html` | 화면 스타일 |
| `Logic.html` | 화면 계산 함수(진행률, 날짜, 집계 등). DOM을 건드리지 않아 Node로 테스트됨 |
| `Client.html` | 화면 그리기와 서버 호출. **서버에서 온 모든 값은 `esc()`로 이스케이프해서 표시** |
| `tests/run.js` | `Schema.gs`, `Lib.gs`, `Logic.html`의 자동 테스트 (구글에 올라가지 않음) |

저장소 루트의 `tools/`는 개발용 도구입니다 (구글에 올라가지 않음).

| 도구 | 용도 |
|---|---|
| `tools/legacy-check.js` | 엑셀을 이관 규칙에 넣어 보고 **집계와 경고만** 출력 (이름·연락처·주민번호는 출력하지 않음) |
| `tools/build-preview.js` | 구글 없이 가짜 데이터와 가짜 서버로 화면을 브라우저에서 띄우는 미리보기 파일 생성 |

## 2. 처음 설정하는 순서 (이미 완료됨. 새로 구성할 때 참고)

1. **도구**: Node.js LTS, Git 설치 → `npm install -g @google/clasp`
2. **구글**: 소유자 계정에서 2단계 인증 확인, https://script.google.com/home/usersettings 에서 Apps Script API 켜기
3. **로그인**: `clasp login` (소유자 계정으로)
4. **프로젝트**: 이 저장소의 `.clasp.json`이 이미 스크립트에 연결돼 있다. 새로 만들려면 `clasp create --type standalone --title "곁마을 운영 대시보드" --rootDir app`
5. **업로드**: `clasp push`
6. **초기 설정**: Apps Script 편집기에서 `Setup.gs`를 열고 `setup` 함수를 실행한다. 처음에는 권한 승인 창이 뜨고, "확인되지 않은 앱" 경고는 고급 → 이동으로 넘어간다 (개인용 스크립트라 정상)
7. **배포**: `clasp create-deployment --description "..."` 로 웹앱 배포를 만든다
8. **확인**: 배포 주소를 열어 앱이 뜨는지 본다

> Apps Script 편집기의 함수 목록은 **지금 열려 있는 파일**의 함수만 보여 줍니다. `runSelfTest`는 `SelfTest.gs`를, `setup`은 `Setup.gs`를 연 상태에서 고르세요.

## 3. 코드를 고치고 반영하는 방법

```
node app/tests/run.js                 # 1) 자동 테스트 (프로젝트 폴더에서)
clasp push                            # 2) 코드를 구글에 올림
clasp create-deployment --deploymentId <배포ID> --description "변경 내용"   # 3) 실제 주소에 새 버전 반영
git add -A ; git commit -m "변경 내용"   # 4) 이력 남기기
```

- 3번에서 **기존 배포 ID를 지정**해야 웹앱 주소가 바뀌지 않는다. ID를 빼면 새 주소가 생긴다.
- 화면을 고쳤다면 반영 전에 미리보기로 확인할 수 있다: `node tools/build-preview.js 출력.html --screen=dash` 후 브라우저로 연다. (`--screen=dash|sess|people|sessions|imp|staff`, 그 밖의 옵션은 파일 맨 위 설명 참고)
- 새 PowerShell 창에서 `clasp`, `node` 명령을 못 찾으면 창을 새로 열거나 `$env:Path += ";$env:APPDATA\npm"` 을 실행한다.
- Apps Script 편집기에서 코드를 직접 고쳤다면 `clasp pull`로 이 폴더에 가져와 어긋나지 않게 한다.

## 4. 시험하는 방법

| 시험 | 방법 | 확인할 것 |
|---|---|---|
| 자동 테스트 | `node app/tests/run.js` | 모두 통과. 쓰기 규칙, 주민번호 거부, 이관 규칙, 화면 계산을 검사 |
| 서버 자체 시험 | Apps Script 편집기 → `SelfTest.gs` 열기 → `runSelfTest` 실행 → 실행 로그 | 모든 줄이 "통과", 마지막 줄 "모두 통과". **운영 DB의 임시 복사본**에서만 돌리고 끝나면 복사본을 지우므로 실제 데이터는 바뀌지 않음 |
| 이관 사전 점검 | `node tools/legacy-check.js "엑셀 경로"` | "기대 결과와 모두 일치", 오류 0개 |
| 접근 통제 | 시험용 구글 계정을 운영진으로 추가·삭제하며 접속해 본다 | 추가 전: 구글 기본 오류. 추가 후: 앱 열림(소유자 메뉴는 안 보임). 삭제 후: 다시 구글 기본 오류 |

## 5. 운영 방법

### 운영진 추가·삭제 (소유자)
앱의 **운영진 관리** 메뉴(소유자에게만 보임)에서 이름과 구글 이메일을 넣고 "추가하고 공유하기"를 누르면 운영진 목록 등록과 파일 공유(운영 DB, 주민번호 파일)가 함께 됩니다. 삭제하면 바로 접속이 막히고 공유가 해제됩니다. 공유가 빠진 사람은 목록의 "다시 공유"를 누르세요. 백업 폴더는 소유자 전용이라 공유하지 않습니다.

### 기존 엑셀 이관 (이미 완료)
2026-11-18에 일해보기 1~5회차를 이관했습니다 (회차 5 · 사람 33 · 참여 기록 34). `Config`의 `legacy_imported = Y`이면 중복 이관이 막히고, 앱의 "기존 엑셀 이관"에서 **되돌리기**(이관분만 삭제)를 할 수 있습니다. 이관 규칙은 [PRD.md](../PRD.md)의 "기존 엑셀 이관 규칙"이 기준입니다. 주민번호는 이관하지 않았습니다.

### 참석 정리, 이동수단, 동의 항목
이관 직후에는 종료된 회차의 참석이 비어 있고, 동의 항목은 "미확인"입니다. 회차 상세의 "참석 전원 처리"와 참여자 상세의 수정 기능으로 채웁니다.

## 6. 스크립트 속성 (Apps Script 편집기 → 프로젝트 설정 → 스크립트 속성)

| 이름 | 내용 |
|---|---|
| `DB_ID` | 운영 DB 스프레드시트 ID |
| `RRN_ID` | 주민번호 스프레드시트 ID |
| `ROOT_FOLDER_ID` | 드라이브 `곁마을 운영` 폴더 ID |
| `BACKUP_FOLDER_ID` | `곁마을 운영/백업` 폴더 ID |

`setup()`이 자동으로 채운다. 이 값을 지우고 `setup()`을 다시 실행하면 **새 파일이 또 생기므로**, 지우지 않는다.
복구 때 운영 DB를 백업본으로 바꾸려면 `DB_ID`만 백업본의 ID로 바꾼다.

## 7. 소유자와 소유권 이전

- 소유자 이메일은 `Schema.gs`의 `OWNER_EMAIL`에 있다. 이 계정만 `setup()`과 소유자 전용 기능(운영진 관리, 이관, 백업)을 쓸 수 있다.
- 폴더, 시트 2개, 스크립트 프로젝트의 소유자는 모두 같은 계정이어야 한다. (연말 영구 삭제, 백업 정리, 운영진 공유 관리를 소유자만 할 수 있기 때문)
- 소유자를 바꿀 때: ① 드라이브에서 `곁마을 운영` 폴더와 파일 2개의 소유권을 새 계정으로 이전 ② Apps Script 프로젝트를 새 계정과 공유 후 소유권 이전 ③ `OWNER_EMAIL` 수정과 `Staff` 탭의 role 변경 ④ 새 계정에서 `clasp login` 후 배포를 다시 만든다.

## 8. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 구글의 기본 오류 "요청한 문서를 액세스할 권한이 없습니다." (우리 화면이 아님) | 그 계정에 운영 DB 스프레드시트가 공유돼 있지 않다. 접근 통제가 정상 작동한 것이다. 앱의 운영진 관리에서 추가하거나(공유됨), 이미 추가했다면 "다시 공유"를 누른다 |
| "등록된 운영진이 아닙니다" | 운영 DB의 `Staff` 탭에 그 이메일이 있고 `active`가 `Y`인지 (대소문자는 무시됨) |
| "아직 초기 설정 전입니다" | 스크립트 속성에 `DB_ID`가 없다. 소유자가 `setup()`을 실행한다 |
| "현재 파일을 열 수 없습니다. 주소를 확인한 다음 다시 시도해 주세요" (구글 드라이브 화면, 주소에 `/u/2/` 같은 부분이 붙음) | 한 브라우저에 구글 계정이 여러 개 로그인돼 있어서 구글이 잘못된 계정으로 열려는 것이다. **시크릿 창을 열어 해당 계정 하나만 로그인한 뒤** 웹앱 주소(`/exec`, 뒤에 `/u/숫자/` 없이)를 열거나, 크롬 프로필을 계정별로 나눈다. 앱의 설정 문제가 아님 |
| 접속 때 권한 승인 창이 계속 뜸 | 새 권한 범위를 추가했을 때 정상이다. 한 번 승인하면 된다 |
| `setup()`이 "소유자만 실행" 오류 | 소유자 계정이 아닌 계정으로 실행했다. 소유자 계정으로 전환한다 |
| `clasp push` 실패: Apps Script API 오류 | https://script.google.com/home/usersettings 에서 API를 켠다 |
| 이관 화면에서 "엑셀 읽기 도구를 불러오지 못했어요" | 엑셀 읽기 도구(SheetJS)를 인터넷에서 불러오는데 실패했다. 인터넷 연결을 확인하고 새로고침한다 |
| 이관 화면에서 "주민번호 열을 찾지 못했어요" | 엑셀의 주민번호 열 이름에 "주민번호"가 들어 있는지 확인한다. 그 열의 값이 모두 비어 있다면 그대로 진행해도 된다 |
| 저장이 "다른 운영진이 먼저 수정했어요"로 거부됨 | 정상이다. 같은 행을 다른 사람이 먼저 고쳤다. 화면이 새로 불러오므로 다시 고친다 |
| 자체 시험(`runSelfTest`)에서 "실패" 줄 | 줄의 설명을 보고 해당 기능을 확인한다. 임시 복사본만 쓰므로 실제 데이터는 영향 없음 |
